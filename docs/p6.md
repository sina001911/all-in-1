# P6 — OpenCode plugin binding (final layer)

P6 turns the package into a real OpenCode plugin and closes the last guarantee in
the four-layer architecture: the **OpenCode tools are the only file writers**.

P1–P5 built the engine, perception, registries, execution gates, specialists,
and the HITL workflow. P5 ended with one open item: `assertCanEdit` was declared
but never asserted, because P5 had no edit action. P6 is the point at which an
edit surface first becomes conceivable — a BUILD command can hand back a plan
that describes edits — so P6 asserts the gate at that boundary.

## What P6 adds

| Module | Role |
|---|---|
| `src/opencode-plugin.d.ts` | Ambient contract for `@opencode/plugin` — the verified SDK surface, so the package type-checks with zero npm dependencies |
| `src/plugin/index.ts` | The **only** runtime SDK import; `Plugin.define` and the command registration |
| `src/plugin/commands.ts` | The five commands and the session-delivery seam |
| `src/plugin/execute.ts` | Routes a command through the P5 specialist stack and the P4 engine; mode enforcement |
| `src/plugin/plan-gate.ts` | The P6 edit boundary — `assertCanEdit` at the moment an edit-capable plan is produced |
| `src/plugin/prompt.ts` | Pure parsing of command text (`--auto`, `--steps`, `--plan`) |
| `src/index.ts` | Package entrypoint; re-exports the plugin |

`src/opencode-plugin.ts` (the P1 local type shim) is **removed**: the ambient
contract replaces it.

## The commands

| Command | Mode | Delivers |
|---|---|---|
| `all-in-1-inspect` | INSPECT | Structured analysis. Read-only, no plan |
| `all-in-1-suggest` | SUGGEST | Analysis + an advisory plan. Proposes, applies nothing |
| `all-in-1-build` | BUILD | Analysis + an edit-capable plan + the edit disclaimer |
| `all-in-1-specialist` | INSPECT | One named specialist (`<id> <subject>`) |
| `all-in-1-policy` | — | The frozen defaults the plugin enforces |

Flags (parsed by `src/plugin/prompt.ts`): `--auto` (explicit autonomous opt-in,
BUILD), `--steps role,role`, `--plan` / `--no-plan`. Unknown roles and unknown
flags are a typed `COMMAND_PARSE` error rather than silently misrouted text — a
silent misroute of a BUILD request would be a safety bug.

Every command runs through `buildSpecialistStack()` → `SpecialistRunner` /
`WorkflowLoop` → the P4 `ExecutionEngine`, so every gate applies unchanged:
SELECT → VALIDATE → EGRESS → APPROVAL → RESERVE → INVOKE → SETTLE.

## The edit boundary

```
assertEditPlanAllowed(mode)  →  assertCanEdit(mode)      (frozen safety/guard.ts)
```

- INSPECT and SUGGEST cannot produce an edit-capable plan — throws the frozen
  `ModeViolationError`.
- BUILD can, and every edit-capable deliverable carries this disclaimer:

  > This is a plan, not an edit. all_in_1 never writes files. Apply it with the
  > OpenCode write/edit/patch tools under human supervision.

The plugin registers **commands only** — no provider, no model, no tool, no
integration. The only file writers remain the OpenCode tools; this plugin binds
commands, not writers. `--auto` stays an explicit, bounded opt-in
(`maxIterations: 5`), verified by the same test that pins it for the CLI.

## Why a binding, not a dependency

Verified against `@opencode/plugin@2.0.22` on Node 24.21.0 (re-verified at P6;
see `docs/architecture.md`):

1. It is not resolvable from this project's directory (`MODULE_NOT_FOUND`); only
   the OpenCode host can resolve it. A dependency would rely on parent-directory
   hoisting.
2. `tsc --noEmit --strict` against it emits TS7016 from a transitive gap
   (`@ai-sdk/provider` → `json-schema`, no types). Closing that requires patching
   a transitive package.

Both violate the isolation requirement. The binding keeps the runtime import
genuine (the host supplies the module) while the ambient contract keeps
type-checking deterministic with `dependencies` empty and no `node_modules`
present.

### Re-verification procedure

To re-verify the ambient contract against a published SDK version:

```sh
# in a throwaway directory, never in this project
npm i @opencode/plugin@<version>
node -e "console.log(require('@opencode/plugin/package.json').version)"
# then type-check a probe import against the installed package:
#   node node_modules/typescript/bin/tsc --noEmit --strict \
#     --module nodenext --moduleResolution nodenext probe.ts
```

and compare `dist/promise/plugin.d.ts` (`Plugin.define`, `Plugin.Context`),
`dist/promise/command.d.ts` (`CommandDomain`, `CommandEditor`,
`CommandDefinition`, `CommandInvocation`), and the `session.prompt` input shape
against `src/opencode-plugin.d.ts`. If the surface changed, update the ambient
contract and the version pinned in it. `test/p6-plugin.test.ts` fails if the
declared names or the pinned version drift.

## Verification

| Check | Result |
|---|---|
| `tsc --noEmit` | clean, with **zero** npm dependencies and no `@opencode/plugin` installed |
| `npm test` | 32 files / 375 tests pass (P5 ended at 31 / 343); P6 adds 1 file / 32 tests |
| Runtime SDK imports | exactly one module (`src/plugin/index.ts`); every other SDK reference is `import type` |
| File writes from the plugin layer | none — structural test scans `src/plugin/*` for any filesystem write API |
| Frozen defaults | untouched: deny-all egress, budget 0, only the local adapter/models, `apiKeyEnv: null`, media gated, MAIN_CODER immutable |
| `opencode.jsonc` / `.opencode` | untouched; no `.opencode` directory exists in this project. Loading the plugin is the user's config change |
| Activation | not auto-loaded; requires the user to add the package to `plugins` in their OpenCode configuration |

## What P6 deliberately does not do

- **No file writes.** The plugin produces plans; the OpenCode tools apply them.
- **No provider, model, tool, or integration registration.** Opening a remote
  provider remains three explicit human acts outside the plugin.
- **No media.** Media stays gated; `MEDIA_DISABLED` still fires.
- **No credential.** `apiKeyEnv: null` on the only registered adapter; nothing is
  read from the environment.
- **No auto-activation.** Nothing in this package modifies any OpenCode
  configuration.
