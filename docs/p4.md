# P4 — Execution Layer: Capability Selection, Egress Security, Live Invocation

## What P4 adds

The first **real call path**. P3 built the capability layer — catalogue,
capabilities, priority chains, provider adapters — but left it unwired: every
adapter's `invoke()` threw `NOT_IMPLEMENTED` and no code path could reach a
model. P4 turns that seam into a working, gate-ordered execution engine, and
gives the P3 `SelectionDecision` / `TraceEntry` contract its first producer.

```
SelectionRequest ──▶ SELECT ──▶ VALIDATE ──▶ APPROVAL ──▶ EGRESS ──▶ SECRET ──▶ RESERVE ──▶ INVOKE ──▶ SETTLE
                   (selector)  (frozen P3)  (approval)  (egress)  (secrets)  (budget)  (adapter) (commit/release)
                   deterministic             policy       security   the only    ledger    transport   never both,
                   side-effect free          gate         gate       key read                          never neither
```

Under the shipped defaults the whole pipeline is **complete but inert**: no
remote provider is registered, egress is deny-all, the budget is 0, and only the
deterministic local adapter exists. Opening a real provider is three explicit,
separate human acts — register the adapter, allowlist its host, grant the
approval — and no frozen default performs any of them.

## Modules

| Module | Owns |
|---|---|
| `src/execution/selector.ts` | The `selection.ts` P3 referenced but never shipped. Pure, deterministic, side-effect free: turns a `SelectionRequest` into an explained `SelectionDecision` with a full `TraceEntry[]`. Classifies cost with the frozen vocabulary; never touches the ledger |
| `src/execution/engine.ts` | `ExecutionEngine` — wires the gates in one fixed order. The order is a security property, not an implementation detail |
| `src/execution/egress.ts` | The model-endpoint network boundary. Default `deny-all`; loopback always permitted; remote requires https + explicit allowlist. Deliberately separate from P2's browser-scoped `safety/hosts.ts` |
| `src/execution/secrets.ts` | The **only** module that reads a secret *value*, at call time. Never stored, never logged, never embedded in an error |
| `src/execution/local-adapter.ts` | The deterministic, zero-network adapter — the only one registered by default — plus `registerLocalModels()` |
| `src/execution/openai-compatible-adapter.ts` | The real remote adapter: Chat Completions over an injectable transport. **Not registered by default** |
| `src/execution/adapter-registry.ts` | Maps adapter ids to live adapters — *how to reach* a provider, nothing about cost or capability |
| `src/execution/types.ts` | The `ProviderInvokeResult` contract that replaces `Promise<never>` |
| `src/execution/index.ts` | Public surface of the layer |
| `src/execution/test-fixtures.ts` | Offline catalogue fixtures so the selector and engine are testable without a provider |
| `src/registry/bridge.ts` | The **only** place that translates between the frozen role vocabulary and the capability vocabulary |

## The gate order, and why it is fixed

1. **SELECT** — deterministic, no side effects, fully traced. No candidate is
   ever forced: a chain entry or preference that fails a check is *skipped and
   recorded* (a chain is a preference, not an authorization).
2. **VALIDATE** — frozen P3 provider isolation (`MODEL_NOT_FOUND`,
   `PROVIDER_ISOLATION_VIOLATION`, `MODEL_UNAVAILABLE`, `CAPABILITY_NOT_SUPPORTED`).
3. **APPROVAL** — a paid or unknown-cost model with no recorded approval stops
   here, before any credential is read or budget reserved (`APPROVAL_REQUIRED`).
4. **EGRESS** — the endpoint host must be allowlisted, **before any key is
   read**. A key must never be read for a destination that will be refused —
   reading it first would hand a credential to a caller with no right to it.
5. **SECRET** — read only after the destination is cleared, and passed straight
   to the adapter for one request.
6. **RESERVE** — budget reserved before the call. Unknown cost reserves 0,
   mirroring the frozen router.
7. **INVOKE** — the single network seam (the adapter's transport).
8. **SETTLE** — commit the *actual* cost on success, release on failure, in a
   `try/catch` so the ledger can never leak a reservation.

## Contract boundaries (verified by tests)

1. **The default egress policy is deny-all.** No remote host is reachable until a
   user explicitly allowlists it; loopback is always permitted (fixture servers)
   and a remote endpoint must use https even when allowlisted.
2. **Egress precedes the secret.** A refused destination never causes a key to
   be read — pinned by a test that asserts `keyWasRead === false` alongside the
   `EGRESS_BLOCKED` failure.
3. **A secret is read once, at call time, and never surfaces.** A missing key is
   a typed `CREDENTIAL_UNAVAILABLE` failure — never a prompt, never a guess, and
   never a silent keyless fallback. The value cannot reach an error message even
   when a network error echoes it back (redaction is applied defensively).
4. **The selector is pure.** It never reserves budget and never reads a
   credential; it only *classifies* cost. `requiresApproval` is information for
   the engine to enforce, not a spend authorization.
5. **Cost is classified with the frozen vocabulary.** `FREE → free`,
   `PAID → premium`, `UNKNOWN_COST → unknown`; unknown is never treated as free
   and always requires approval. `FREE_ONLY` blocks paid; nothing else does so
   silently.
6. **Budget settlement is exact.** On success the reservation is released and
   the *actual* reported cost is committed (so an over-estimate is never pinned
   to the ledger); on failure the reservation is released and nothing is spent.
7. **Provider isolation still holds on the live path.** The frozen P3
   `validateInvoke()` runs before any call.
8. **The OpenAI-compatible adapter never imports an HTTP library.** The
   transport is injectable; the default uses global `fetch`, so the package keeps
   **zero runtime dependencies**. Every failure class maps to a typed error with
   correct retryability (`429` and `5xx` retryable; `401/403` and other `4xx`
   not).
9. **The frozen role layer is untouched.** The bridge *translates*; it never
   merges. Role resolution still goes through the frozen `ModelRouter`.

| Category | Codes |
|---|---|

| `config` | `SELECTION_FAILED`, `APPROVAL_REQUIRED`, `BUDGET_EXCEEDED` |

## CLI

```sh
node src/cli.ts select CODING                      # explain selection: model, basis, full trace
node src/cli.ts invoke CODING --text "hello"       # execute end to end (offline by default)
node src/cli.ts invoke CODING --text "hi" --allow-host api.example.com --policy PREMIUM_ALLOWED --budget 5
```

`select` runs the pure selector and prints the decision, including every
candidate considered and the exact reason each was accepted or rejected. `invoke`
runs the full gate pipeline and reports the model, basis, adapter, committed
cost, output, and trace. With no remote provider registered, both resolve to the
deterministic local model — so the entire path is exercisable with no credentials
and no network. A media-gated capability (`IMAGE_GENERATION`) or an unknown one
exits 1 with an explanation.

## Scope refinement vs. the proposal

Egress is an engine option with a secure deny-all default, defined in
`egress.ts`, rather than a new section in `config/schema.ts`. This is strictly
*less* invasive than approved (no frozen-defaults manifest touched) while
preserving the same security property — the default permits no remote egress, and
the allowlist grows only through an explicit `allowHost()` call.
