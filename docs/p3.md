# P3 — Vision Layer, Model & Capability Catalogue, Provider Adapters

## What P3 adds

The perception contract and the vocabulary the rest of the system routes against.
The vision layer turns a P2 screenshot artifact into deterministic, schema-valid
structured JSON. The model catalogue and capability system describe *what a model
can do* without ever calling it, and the provider adapter defines how a provider is
represented — metadata and validation only.

```
ScreenshotEngine ──▶ captureAndAnalyze() ──▶ VisualAnalyzer ──▶ VisionProviderRegistry
                         │                        │                    │
                    artifact kept on              │            deterministic fake
                    analysis failure          ModelRouter (FROZEN)      (only registered
                         │                  FREE_ONLY / budget=0        provider)
                    ArtifactStore
```

## Contract boundaries (verified by tests)

1. **The vision layer has no pricing logic of its own.** It routes the `VISION`
   role through the *existing, frozen* `ModelRouter`, so `FREE_ONLY`,
   `spendBudgetUsd = 0`, and `UNKNOWN_COST` blocking apply unchanged. No pricing
   rule is duplicated in the vision layer.
2. **Analysis never blocks on missing credentials.** When the router can only
   resolve a stub (no real model qualifies under the frozen policy), the
   deterministic fake is the genuinely zero-cost path — and the chosen provider
   is recorded in the output, so the caller always knows which engine answered.
3. **The locale contract is enforced.** A provider that ignores the requested
   locale raises `VISION_CAPABILITY_MISMATCH`; a provider that honours it
   (e.g. `fa` → `rtl` reading direction) is verified by test.
4. **The screenshot survives an analysis failure.** `captureAndAnalyze()` returns
   both outcomes, so a late perception failure can never discard an already-stored
   artifact or its provenance.
5. **Provider isolation is enforced structurally.** A model may only be served by
   the adapter that owns its provider id, and only for capabilities that adapter
   is registered to serve (`MODEL_NOT_FOUND`, `PROVIDER_ISOLATION_VIOLATION`,
   `MODEL_UNAVAILABLE`, `CAPABILITY_NOT_SUPPORTED`).
6. **Paid models stay *visible* while policy blocks them.** `candidatesFor()`
   filters on capability + enabled + available + non-fixed + selectable status —
   never on cost — so the selector can explain a rejection instead of hiding it.
   The `fixed` flag mirrors the frozen `MAIN_CODER` immutability rule.
7. **No provider performs network I/O in P3.** `invoke()` is declared by the
   contract but throws `NOT_IMPLEMENTED` (`retryable: false`); adapters are
   metadata + validation only. Secrets are referenced by environment-variable
   **name** only — never read, stored, or logged.
8. **Capability ids are opaque, extensible strings.** An *unknown* capability is
   not an error: it simply carries no hard modality requirements, so a capability
   added later routes identically to a baseline one.
9. **The capability cost vocabulary projects onto the frozen policy set without
   modifying it.** `FREE → free`, `PAID → premium`, `UNKNOWN_COST → unknown`, and
   `ASK_BEFORE_PAID → PREFERRED_FREE`; the frozen `COST_POLICIES` and `PRICING`
   tuples are untouched.

## Typed failure model

P3 adds these codes to the existing categories:

| Category | Codes |
|---|---|
| `unavailable` | `VISION_PROVIDER_UNAVAILABLE`, `MODEL_UNAVAILABLE`, `NOT_IMPLEMENTED` |
| `browser` | `VISION_ANALYSIS_FAILED` |
| `artifact` | `IMAGE_TOO_LARGE` |
| `config` | `UNSUPPORTED_IMAGE`, `VISION_CAPABILITY_MISMATCH`, `MODEL_NOT_FOUND`, `CAPABILITY_NOT_SUPPORTED` |
| `security` | `PROVIDER_ISOLATION_VIOLATION`, `CAPABILITY_NOT_SUPPORTED` |

`NOT_IMPLEMENTED` is deliberately permanent in P3: `retryable: false`, because a
retry will not make a metadata-only adapter live. Live invocation is P4.

## CLI

```sh
node src/cli.ts analyze http://127.0.0.1:<port>/   # capture + store + structured analysis
```

`analyze` reuses the P2 `shot` path for capture and storage, then runs the
vision layer. The response reports the screenshot artifact *and* the analysis
side by side, with `analyzerId` naming which engine answered and `analysisError`
set only when perception failed after a successful capture.

## Relationship to the frozen P1 layer

The frozen role-tagged `ModelDefinition` registry is untouched. `ModelDescriptor`
is the richer capability-tagged catalogue; the two are bridged, not merged. Cost
is still enforced through the frozen `Pricing` taxonomy via `toPricing()`, and
role resolution still goes through the frozen `ModelRouter`. P3 adds vocabulary
and perception; it changes no accepted default.

## Frozen defaults

All P0/P1/P1.1/P2 frozen contracts are unchanged: MAIN_CODER immutability,
`spendBudgetUsd = 0`, `FREE_ONLY`, `UNKNOWN_COST` blocked, no silent free → paid
fallback, media disabled, zero **runtime** dependencies, and no `opencode.jsonc`
change.
